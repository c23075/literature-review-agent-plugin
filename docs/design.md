# Design

Moved from Cairnward's spec with ADR-0017. It describes the research workflows as they
were built in the core. What changed: models go through the gateway, outside requests through the
fetch service, library keys through the key service, jobs run in this plugin, and commands are
`cairnward-research`, not `cairnward`. Decision numbers are kept from Cairnward's spec.

## Decisions
| # | Decision | Choice | ADR |
|---|---|---|---|
| D63 | Tiered research pipeline | Main model screens titles/abstracts (changed 2026-11-03: on the reference machine the fast model excluded every relevant paper, see `docs/bench/results-2026-11-03-screening.md`) and reads only included papers; full-text reading is an overnight job (~5–8 papers/hour) | — |
| D67 | Reference formatting (revised 2026-11-02) | **Selectable CSL engine**, `[research] citation_engine = auto | builtin | citeproc-js | pandoc`; auto = citeproc-js (Zotero's engine, Node, installed pinned) if installed, else pandoc, else the built-in APA/IEEE formatter (always available, the fallback). Official APA 7 and IEEE CSL files and the en-US locale vendored unmodified (CC BY-SA 3.0), hash-checked. citeproc-py was tested and rejected: wrong sorting of accented names, capitalisation, conference papers and punctuation in quotes | — |
| D68 | Richer PDF parsing | Optional sandboxed workers with **split roles**: **Docling** for body text, tables and OCR; **GROBID** for title/authors/DOI and the reference list; pypdfium2 stays the default and fallback; switched on per library | — (extends D53) |
| D7, D25 | Literature sources, citations | Local PDFs, Zotero, arXiv/Semantic Scholar/OpenAlex/PubMed/Crossref; CSL styles (APA, IEEE default) | — |

### 4.6 Research workflows (D7, D25, G5)
- **Jobs**, not chat turns: `cairnward-research research review --question "..." --library thesis --style apa` queues a job; the dashboard shows progress; jobs are **resumable** after a restart and can be scheduled ("run overnight"). On CPU, a review of tens of papers is expected to take hours; that's the design point.
- Pipeline: library (local PDF folder, Zotero via local API) and optional search (arXiv, Semantic Scholar, OpenAlex, PubMed, Crossref, network opt-in) → dedupe → screen (criteria; **titles and abstracts with the main model**, D63) → extract per paper (claims, methods, datasets, limitations) → synthesise → **citation check** (every reference must resolve to an indexed paper or DOI; every quotation must match the PDF text) → format (CSL: APA, IEEE; `.csl` files add styles).
- Outputs: comparison table, synthesis draft, `.bib`/CSL-JSON, written to a git-versioned artifacts folder.
- Interactive use: the same capabilities are exposed as MCP tools (`lit.search`, `lit.ask` with page-cited answers, `lit.review.start`), so any chat client can use them.
- **Libraries (implemented in T1.2):** `cairnward-research library create <name> <folder>` registers a folder of PDFs under an environment; `library index` parses them with pypdfium2 (page by page; words hyphenated across lines rejoined), splits them into ~350-token chunks along paragraph and sentence boundaries with ~60 tokens of overlap, records the pages each chunk spans, and embeds them through the policy engine (audited like gateway calls). Storage is `research.db`: documents, chunks, an FTS5 keyword index and a sqlite-vec vector table per library. Search fuses vector and keyword rankings (reciprocal rank fusion), so exact terms are found even when embeddings miss them. Indexing is resumable: each paper is committed on its own, unchanged files (same SHA-256) are skipped, deleted files are excluded from search until `--prune`, and a returning unchanged file is re-enabled without re-embedding. Scanned PDFs without text are flagged (`no_text`; OCR later) and broken ones reported. Changing the embedding model requires `--rebuild`. Chunk text is stored as plain text in the owner-only data folder until library locking arrives (M2).
- **lit.ask (implemented in T1.3):** hybrid search picks up to 8 passages (fewer if they don't fit the virtual model's context with room for a 1,024-token answer, plus 2,048 tokens of reasoning when the effort level turns reasoning on, lowest-ranked dropped first); the environment's model answers from the numbered passages only, citing claims as [n], or says "I can't answer this from these sources". Citations are mapped to file and pages; citations to passages that weren't given are removed (shown as [?]) and reported; an answer with no citation is marked uncited; a reply stopped by the token limit is marked cut off, with a warning that says so (and that there's no answer, if it stopped before answering). Model calls go through policy, redaction (non-local backends) and audit like gateway calls, and inside the server they wait in the gateway's per-backend queue. Available as `cairnward-research library ask` (through the running server when there is one), the management API and the MCP tool `cairnward__lit_ask`; audited as `research.ask` with the question as a digest only. Eval: `evals/pdf_qa` (synthetic papers with facts on known pages, two unanswerable questions), to be run with the real models.
- **Locking a library (FR-ENC-1, T-24):** `cairnward-research library lock | unlock | recover <name>`. A library's documents, chunks, keyword index, embeddings and GROBID metadata become one file (`library-locks/<name>.age`) encrypted with a new key, wrapped by the passphrase and covered by the recovery key; the rows are deleted, the keyword index rebuilt and the database vacuumed, so a test finds none of the text in the data folder's bytes. PaperQA2's cache for it is deleted. The name, folder and environment stay readable. While locked it can't be searched, asked or indexed, and models don't see it. Unlocking removes the lock until you lock again; there's no timed unlock, because search needs the rows in `research.db`. The source PDFs aren't touched, and older backups still hold the index. Backups include the sealed file and the wrapped keys of locked items, and `backup restore` brings the keys back.
- **Citation and quotation checks (implemented in T1.5):** every quotation (12+ characters in quotes) in a lit.ask answer is looked up in the passage it cites, then in the same paper, then anywhere in the library (matching ignores case, whitespace, quote and dash styles, soft hyphens and words split across lines); misplaced or missing quotes are reported with the answer. The required refusal sentence in quotes doesn't count as a quotation, a stray quote mark doesn't pair with the next quotation, and a quotation with no citation only has to be found in the papers. Reworded quotations and quoted short phrases that aren't in the papers are still reported. `cairnward-research library check <library> <draft.md>` checks a draft: each quotation must be found in the library (with title and pages), and each entry of a References/Bibliography section must match an indexed paper's title; DOIs are only checked for form offline (resolving them needs the network, a later research step). `evals/pdf_qa` counts invented citations and unfound quotations together (must be zero).
- **Reference formatting (implemented in T1.6):** `cairnward-research cite refs.json --style apa|ieee` formats CSL-JSON (Zotero's export) as APA 7 or IEEE, implemented directly for journal articles, books, chapters, conference papers, reports, theses, web pages and preprints (APA: up to 20 authors, then 19 + ellipsis + last, alphabetical, accent-insensitive; IEEE: numbered in order, more than 6 authors as "et al."), with APA in-text citations; Markdown italics or `--plain`. Titles are used as given (no automatic sentence case). Other styles: a `.csl` file through the optional citeproc-py package (the official APA/IEEE `.csl` files aren't shipped). `cairnward-research library refs <name>` exports CSL-JSON from the papers' PDF metadata as a starting point. Golden tests in `tests/data/`.
- **Jobs (implemented in T1.4):** a job is a list of steps saved to `<data>/jobs/<id>/job.json` after every step (atomic writes); the runner in the core takes one job at a time, its model calls wait in the gateway's per-backend queue, and after a crash or restart it continues from the first unfinished step (tested by interrupting a review mid-run). Jobs can start later (`--at 23:30` or an ISO time) and be cancelled. Types: `ask` (lit.ask for each question in a file) and `review`, the first slice of the review pipeline (FR-RES-4). A review picks its papers when it starts, not when it's queued: its first step indexes the library (incrementally, audited with the job as actor) so PDFs added before a scheduled start are included; `--files a.pdf b.pdf` or `--files-from list.txt` limit it to those PDFs (inside the library folder; only they are indexed, and files not there yet are reported at submit and listed as not reviewed in the result). Then the environment's model reads each paper (as much as fits the context) and writes JSON notes (aim, method, sample, findings, limitations, with pages); a comparison table and a bibliography (APA/IEEE) are then assembled without a model into `result.md`; a failed paper doesn't stop the job. `cairnward-research research review|ask`, `cairnward-research jobs list|show|cancel|result`, the dashboard's Research jobs view, and the MCP tool `cairnward__lit_review_start`. Screening, search and synthesis come with the full pipeline (M3).
- **Throughput on the reference machine (D63):** screening an abstract (~300 tokens) with the main model takes ~2 min, reasoning included; reading a full paper (~8–10K tokens) with the main model takes ~6–8 min plus a few minutes of writing notes, so **about 5–8 papers per hour, 40–60 per night**. Jobs are planned with these numbers and show an estimated finish time. Work is grouped by model (all embeddings, then all screening, then all full-text reading) so models aren't loaded and unloaded repeatedly.
- **Engine (ADR-0014, decided in T1.1):** Cairnward's own lean pipeline is the default (~2–3 min per question on the reference machine). PaperQA2 is an optional "deep" engine for overnight jobs, run as a separate sandboxed worker with every call through the gateway; measured at ~11 model calls and ~15K input tokens per question (≈ 8–10 min here), so it's kept out of the interactive path and out of the core's dependencies. Other prior art studied: Zori, ZotLLM (citation and quote checking), STORM, GPT Researcher.
- **PaperQA2 deep engine (implemented, FR-RES-13):** `cairnward-research research engine install paperqa` installs paper-qa 2026.8.12 with its 78 dependencies into its own virtual environment in the data folder, from a hash-pinned requirements file (nothing enters Cairnward's core). `cairnward-research library ask <lib> "..." --engine paperqa [--evidence-k N] [--skip-summary]` runs a small worker with that environment's Python like an agent run: a short-lived run key (`run.start`/`run.end`, client `paperqa`), and with isolation on the sandbox with only the gateway reachable; every model call is a gateway call (policy, queue, audit). The worker refuses to start unless every model setting (`llm`, `summary_llm`, `embedding`, `parsing.enrichment_llm`, `agent.agent_llm` and their configs) points at the gateway, online metadata lookups (`use_doc_details`) and image enrichment (`multimodal`) are off and no other URL appears. Its index lives in `$CAIRNWARD_CACHE_DIR/paperqa/<library>/` (default `~/.cache/cairnward`, owner-only), outside the data folder the sandbox hides, and is rebuilt when the models change. Answers are mapped to Cairnward's format (citation keys -> [n] with file and pages; quotation checks), so `evals/pdf_qa --compare` scores both engines on the same questions. Tested end to end in CI (isolated serve, real sandbox, scripted model). Overnight jobs can use it too: `cairnward-research research ask <lib> questions.txt --engine paperqa [--at 23:30]` queues one PaperQA2 step per question; each step gets its own run key (revoked afterwards) and is audited with the job as actor. With isolation on, the core can't start sandboxes, so it asks the outer process over the egress control socket (`POST /v1/engines/paperqa/run`) to run the sandboxed worker; with isolation off the server runs it itself. Tested end to end in both modes. Each model call may take up to an hour, with no retries (the library's default of 60 s with retries failed on the reference machine, where one answer call took 158 s). Real run: see [results-2026-11-03-paperqa.md](bench/results-2026-11-03-paperqa.md). Its index is cached with pickle (loading it runs code), so the worker reads it only when it carries an HMAC made with a key kept in Cairnward's state folder (`paperqa-cache.key`, owner-only, hidden from the sandbox) and passed in on stdin; anything else is ignored and rebuilt. The worker adds to PaperQA2's prompts: summaries must not mention what an excerpt leaves out, and answers must not quote the context or say a source states that something is missing, because the main model read such summaries as the paper's own words. A refusal in other words also counts as `cannot_answer`. Wrong summaries can still reach an answer ([results](bench/results-2026-11-04-paperqa-reruns.md)).
- **Online sources implemented (T3.4, FR-RES-8/9):** OpenAlex, Semantic Scholar, arXiv, Crossref and PubMed, **opt-in per environment** (`research_sources = [...]`; on in the built-in `litreview-online`, off everywhere else). The core runs them: each request is first checked by the policy engine as a `net.connect` to the source's host in the environment (`network = "off"` refuses, `"ask"` asks, an allow-list must list the host; `litreview-online` lists the five API hosts and asks for anything else, such as a repository serving a PDF) and the query is scanned like any outgoing text (`redaction = enforce` blocks secrets); requests leave through egress (or the isolated core's sandbox proxy), so they appear in the egress report; `research.search`/`research.fetch` audit records hold a digest of the query, not the text. Answers are cached in the data folder for a week. Results are merged across sources (by DOI, else title and year). `cairnward-research research search "<query>" [--library L | --env E] [--source S]` lists them with their IDs; `cairnward-research research add <library> doi:... arxiv:...` downloads open-access PDFs (50 MB limit, must be a PDF, each redirect target checked again) into `<library folder>/online/` with a `.csl.json` metadata file next to each, then indexes (the CLI writes the files, since the isolated core can't write to library folders). Citations use a `.csl.json` next to a PDF when there is one. Tested with synthetic responses written from each API's documented format (the build environment can't reach the APIs; to be checked live). An answer larger than 10 MB is refused and not cached.
- **Full review pipeline implemented (T3.5, FR-RES-4, D63):** `cairnward-research research review <lib> --question "..." [--criteria "..." | --criteria @file] [--no-screen]`. Steps, saved after each (resumable): prepare (index, pick papers) → **screen** every paper on its title and abstract with the environment's **main model** at its default effort (the abstract from the paper's `.csl.json` when there is one, else the opening of the paper; decision include / exclude / unsure with a reason; excluding takes two tries that agree, and a disagreement is read as unsure, because the model's answer on a borderline paper varies between tries) → **select** (included and unsure papers go on; a paper that couldn't be screened is read rather than dropped; if every paper is excluded, the result says so first and points to `--no-screen`) → **notes** from the full text of each kept paper → **synthesis** (themes, agreements, differences, gaps; citations by number, each checked: citations to papers that don't exist and uncited papers are listed) → comparison table, references in the chosen style and **`references.bib`** (`cairnward-research jobs result <id> --bib`). All screening runs before any reading. With reasoning on, each reply's token limit includes 2,048 tokens of reasoning, which comes out of the room for the paper's text. The estimated finish time counts each pending step at the average of finished steps of its kind, else the reference machine's measured cost (screen 2 min, notes 7 min, synthesis 5 min), and assumes every paper is read until screening is done. `cairnward__lit_review_start` takes `criteria` too. Measured with real models by `evals/litreview_table` (`cairnward check --review`), owner-side.
- **Richer PDF parsing implemented (T3.6, D68):** per library, `cairnward-research library set <name> --parser docling --metadata grobid` (options in `<data>/library-options.json`; `library index --rebuild` re-reads). **Docling** (MIT; text in reading order, tables as Markdown, OCR) runs as an optional worker from its own virtual environment: `cairnward-research research engine install docling` resolves Docling 2.140.0 with CPU-only PyTorch, **records** the exact versions and hashes in `<data>/engines/docling/requirements.lock.txt` and installs from it with hashes required, then downloads its models once; `install.json` keeps the lock's and the models' SHA-256 and the doctor reports any change. This is trust on first use, chosen by the owner because the build environment can't reach the PyTorch index or Hugging Face; shipping the lock in the repository is a follow-up. The worker gets no network at all and runs in the sandbox when the library's environment has isolation on (the isolated core asks the outer process, `POST /v1/engines/docling/parse`); all of an index run's new or changed PDFs go to one worker run (models load once); any PDF Docling can't read falls back to pypdfium2. **GROBID** (Apache-2.0; title, authors, DOI, journal, abstract and the reference list) is your own service on this machine (`[research] grobid_url`, only loopback accepted; e.g. its container with `--network none`); each new or changed PDF is sent with consolidation off, and the results go to `<data>/library-meta/<library>/` (`.csl.json`, `.refs.json`); a metadata file next to the PDF (Zotero, `research add`) takes precedence over GROBID's, which takes precedence over the PDF's own metadata. A GROBID failure is reported, not fatal. Tested with a stand-in `docling` package (the real worker script) and synthetic TEI written from GROBID's documented format; to be checked with the real tools.
- **Hosted providers implemented (T3.7, FR-BACK-4/5, D70):** `cairnward backend providers` and `cairnward backend template <name>` print ready `backends.toml` blocks for OpenRouter (paid and `:free`), DeepSeek, Alibaba Model Studio, Groq, Cerebras and Gemini (free and paid): OpenAI-compatible, `location = "hosted"`, key from an environment variable, and `trains_on_prompts` set conservatively (true for free tiers and wherever Cairnward can't vouch that the API terms rule out training; the user checks and may change it). Hosted backends stay denied unless `hosted_backends` allows them and are never used for locked conversations (unchanged); a backend marked `trains_on_prompts` is refused outside environments with `scratch = true` (the built-in `scratch` environment has it) while `training_backends = "scratch_only"`, the default in Balanced and Strict; setting it to `allow` is shown as a weakening and audited like any other. `/v1/models` marks hosted virtual models in `owned_by` ("cairnward ☁ hosted", plus "(may train on prompts)").
- **Drive mirror implemented (T3.8, FR-SYNC-2):** `cairnward-research library drive <lib> --remote gdrive:Papers [--preview] [--prune]` copies the PDFs of an rclone remote you set up yourself (`rclone config`; rclone keeps the Google sign-in, Cairnward never sees it; a warning unless the remote has `scope = drive.readonly`) into `<library folder>/drive/`, only new or changed ones, then indexes. Only `config dump`, `lsjson` and `copy` from the remote are run, so nothing on Drive changes; files gone from Drive are reported and kept unless `--prune` (which deletes from `drive/` only). The policy engine checks `net.connect` to `www.googleapis.com:443` in the library's environment first (refused where the network is off, a terminal question where it says ask); each run is audited (`drive.mirror`). rclone's traffic goes through a short egress session in that environment (`HTTPS_PROXY` with a one-run token; `serve` must be running), so the allow-list applies to every host it contacts and its bytes show in the egress report under the client `rclone`; the session ends with the command. Tested with a stand-in rclone, and the egress session against a real `serve` (`tests/isolation/test_tool_egress.py`).
- **Presidio, OpenTelemetry and RFC 3161 implemented (T3.9, FR-RED-2, FR-AUD-5, D69):** *Presidio* (MIT): `cairnward redaction install presidio` (presidio-analyzer 2.2.364 and spaCy's small English model `en_core_web_sm` 3.8.0, installed from `research/engines/locks/presidio.txt`, a cross-platform lock shipped in the repository in which every package and the model wheel are hash-pinned; nothing is resolved on the user's machine), then `[redaction] presidio = true`; its findings (by default PERSON, LOCATION, NRP above score 0.6) join the patterns' as personal data (patterns win on overlapping text). It runs as a long-lived child of whichever process scans (inside the core's sandbox when isolated), with no network; if it fails, the patterns still apply and the audit log notes it was unavailable. `cairnward redaction scan "<text>"` shows what is found. *OpenTelemetry*: `[telemetry] otlp_endpoint` (loopback only) exports finished model, embedding and tool calls as OTLP/JSON spans with the GenAI semantic conventions (operation, provider, model, token counts, duration; Cairnward's environment, client, run and decision), built from the audit log, so never prompts or answers; it keeps its place in `<state>/otel.json`. *RFC 3161*: `[anchor] tsa_url` (and `tsa_ca_file` to verify) timestamps each audit checkpoint with a timestamp authority (only the hash is sent); `audit verify --anchors` checks the tokens. Tested against a real authority run with `openssl ts`, a stand-in `presidio_analyzer` with the real worker, and a mock collector. Presidio since checked for real (2026-11-02): installed from the shipped lock and run through the scanner; this found and fixed a bug the stand-in hid (the worker asked for spaCy's large model, which isn't installed, so Presidio was always "unavailable"). The small model misses some names (e.g. "Grace Hopper" in one test sentence), so treat it as a help, not a guarantee. **Docling's lock** can't be resolved in the build environment (the PyTorch CPU index is blocked): the first install still resolves and records it; `cairnward-research research engine export-lock docling` copies that record to `research/engines/locks/docling-<platform>.txt` for review and commit, after which installs on that platform use it.
- **Zotero implemented (T3.4, FR-RES-7):** read-only through Zotero 7's local API (`127.0.0.1:23119`, "Allow other applications on this computer to communicate with Zotero"); `cairnward-research library zotero <library> [--collection "Thesis/Chapter 2"]` copies each item's first PDF into `<library folder>/zotero/` with Zotero's CSL-JSON next to it, copying only what changed, then indexes; `--list-collections` shows the collections. Only the local API on this machine is accepted. Tested against a fake local API (attachments stored in Zotero's storage, linked files, and the file redirect); to be checked against a real Zotero.
- **Multi-agent orchestration** lives here: workflow steps can fan out per paper as sub-agents (queued, `max_parallel` per backend, 1 on local CPU) with budgets and nested audit records. Workflows are YAML.
- **Workflows implemented (FR-RES-11):** `cairnward-research research workflow <library> <file.yaml> [--question ...] [--at ...]`, with an example in `examples/workflows/`. A step can use `for_each: papers` to run one sub-agent per indexed paper. A sub-agent is one model call with **no tools**, so a paper can only change what it writes. Values go in by name in one pass (`question`, `item.title|path|text`, `steps.<earlier>`), marked as data; there is no expression language. Every workflow has a budget of requests, tokens and model time, and `max_papers`, with defaults; `max_parallel` is capped by the effort level, and an effort level with `subagents.max = 0` can't fan out. Each call is policy-checked and audited under `job:<id>/<step>/<n>`, with counts but no content in `workflow.step` records. Progress is saved after every call, so a stopped job doesn't repeat finished papers, and one failed paper doesn't stop the others. Tested with a scripted model; not yet with a real one.
